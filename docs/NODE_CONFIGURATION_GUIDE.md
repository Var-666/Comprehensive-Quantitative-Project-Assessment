# 节点保存后的配置检查与操作引导

日期：2026-10-22。

## 交付行为

新增节点保存后，在同一个节点抽屉中显示“节点配置结果”：保存状态、已关联动作及模板版本、提醒规则、计划审批状态和下一步建议。可以查看动作、展开提醒规则、返回节点列表或继续添加。候选模板在抽屉内选择，不叠加另一个业务抽屉。只有独立审核人员会看到“前往计划审批”，该入口打开已有的整版计划审批表单；不会逐节点强制审批。

已有节点详情保留节点信息、标准动作、实际记录和变更历史，并增加配置检查。检查失败可重试；公共配置改变后可以重新检查。节点列表保留原字段，新增“配置状态”列和筛选。筛选先计算真实状态、再分页，返回准确的匹配总数。

新建节点可明确选择“仅进行节点计划及完成情况跟踪，不需要标准动作”。选择保存在计划快照，刷新、导入、计划增量继承后仍有效。此类节点不作为缺少动作或规则的异常，不生成准备任务或提醒，仍可提交并独立核实实际完成事实。工作台也按节点进展跟踪展示，不声称其已进入自动提醒流程。

已有动作的节点也可在草稿中明确切换为仅时间记录，须填写原有的变更原因。原动作快照保留并显示“暂不执行”，不会无痕删除；恢复普通跟踪时，仅当前仍合法的关联可继续使用。修改继承节点时仍只实体化该节点，旧版及其实际事实不变；已有生效计划继续执行，直到变更版本独立批准后才按新选择执行。

## 自动关联、事务和权限

- 适用性继续由 `workflow.applicable()` 决定：节点类型、模板项目类型条件及 `approved` 状态全部满足。`suggested-actions`、匹配查询和手动关联沿用这一判断。
- 本次创建/正式导入的草稿节点只有一个适用批准模板时，服务端调用原 `workflow.link_actions()` 关联全部动作。多候选不代选；没有批准模板仍保存节点；草稿、待批准及停用模板不能关联。
- 写入前重新锁定并校验模板。已有 ActionLink 保留，不重复创建；业务编号及关联唯一约束、项目锁和原事务机制继续生效。
- 自动关联保留模板名称、编号、版本、动作、材料、部门、核实依据及 `automatic_node_create` / `automatic_excel_import` 来源，并产生审计。手动关联保留 `manual` 来源。
- 节点及关联写入、配置结果读取在创建事务内完成，失败回滚；正式导入的所有节点与关联处于同一个批次事务，失败不部分提交。
- GET 配置检查只读，不自动补配历史节点。增量草稿没有改动的节点继续引用原快照，不复制关联、不影响已有任务或提醒。需要修改时仍按原逻辑实体化单个节点。
- 节点写入仍要求项目 admin/editor；项目 reviewer/viewer 不能通过检查接口写入。公共模板、规则和日历仍由系统管理员编制、另一名符合条件的审核人员批准。系统管理员不因此获得未授权项目的业务权限。
- 生效/历史计划不允许直接修改关联；须先进入草稿。手动关联使用当前选择的计划版本，包括继承快照所在的变更草稿。

## 提醒检查

检查复用正式提醒引擎的 `trigger_date()` / `calendar_trigger()`，不另建一套日期算法：

1. 查当前节点类型的已批准公共提醒规则；只有草稿/待审核版本时显示待批准，没有规则时显示待配置。不会向节点页面返回未批准规则或模板的配置明细。
2. 对每条批准规则显示编号、版本、提前天数、自然日/工作日、接收角色及可用接收人数。
3. 自然日直接减天数；工作日使用规则引用的已批准日历，检查业务时区、日期区间和倒推所需的每日标记。返回提醒日期或具体不可计算原因。
4. 接收人须有本项目有效授权，角色与规则一致，登录账号启用。缺少接收人时不能标记就绪；不把其他项目的人员计入。
5. 保留现有提醒引擎要求的日期依据检查。动作和规则完整但节点缺少日期依据时，显示待补充。
6. 计划状态单独显示。草稿可以“配置就绪”，但尚未获得整版独立批准，不能由该草稿产生正式提醒。

存在规则不等于已经发送。计划生效、当前有效配置、节点未取消/未核实完成、触发日期或明确追补窗口、有效接收人等原有条件仍由提醒引擎实时校验。节点保存及检查不会发送正式通知，不绕过审批，不确认节点完成或款项到账。

## 配置状态

主要状态按下表及原有有效性计算，完整问题在详情返回。多个问题同时存在时先显示动作问题，再显示提醒问题、日期依据问题；项目关闭、节点取消或移出计划覆盖为停用状态。

| API 状态 | 显示 | 判断 |
| --- | --- | --- |
| `ready` | 配置就绪 | 有合法关联、批准规则可计算且有接收人、日期依据齐全 |
| `actions_pending` | 待关联标准动作 | 没有合法关联，或原关联需复核 |
| `actions_conflict` | 待确认动作模板 | 没有关联且有多个批准候选 |
| `actions_approval` | 动作模板待批准 | 没有可用批准模板，但有适用草稿/待审核模板 |
| `reminder_missing` | 提醒规则待配置 | 动作满足要求，但没有适用批准规则或待批规则 |
| `reminder_approval` | 提醒规则待批准 | 动作满足要求，提醒规则尚无批准版本 |
| `reminder_blocked` | 提醒配置需完善 | 接收角色没有可用账号，或日历/日期计算有问题 |
| `source_missing` | 计划依据待补充 | 动作和提醒满足要求，但缺少计划日期依据 |
| `tracking_only` | 仅时间记录 | 业务人员明确选择仅跟踪计划及完成情况 |
| `inactive` | 节点已停用 | 项目关闭、节点取消或移出计划 |

`ready` 与 `tracking_only` 的 `ready=true` 表示必要配置已满足/无需配置，不代表计划生效或节点完成。后两项仍分别看 `plan.status`、实际记录核实状态。没有检查结果的页面暂显示“待检查”，不猜测为就绪。

## 数据库与 API

新增 Alembic 迁移 `b42d8e910a21`，在 `milestone_plan_items` 增加非空布尔字段 `tracking_only`，默认 false。历史节点保留原匹配语义，不自动改为仅时间记录。字段随原增量快照复制；计划差异及操作记录包含这个业务选择。已有 true 记录时拒绝无保留方案的降级，避免丢失业务决定。


| 接口 | 本次变化 |
| --- | --- |
| `POST /api/v1/projects/{project_id}/milestones` | 接受选填 `tracking_only`；返回 `configuration` 和原 `action_matching`，创建事务成功后才返回保存成功 |

## Excel 导入

原工作簿和默认映射保持可用，新增选填映射“仅时间记录”，列内容可填写“是/否”。不配置该列时默认 false。

预览只写原有预览批次和校验元数据，绝不创建正式节点或 ActionLink。界面显示可自动匹配、多候选、没有模板、模板待批及仅时间记录数量；错误/重复行不计入可导入数量。正式提交会重新归一化、重新判断模板和实际配置，不沿用可能已过期的预览结论。

正式结果来自后端实际事务：显示已导入数量、自动关联/待选择/缺失/待批/仅时间记录计数，每行显示动作结果与综合配置状态。提醒规则、日历和接收角色的检查按项目批量读取，不为每个节点复制公共规则。没有适用模板的行作为待处理保留，不逐行弹出选择框。

继续保留整批原子性、预览摘要、编号二次校验、幂等键、原始行及导入审计。确认后任一关联写入失败则整批回滚；相同幂等请求返回原结果。

## 完整手动验收

1. 升级数据库，启动原开发服务。准备系统管理员编制账号、一个独立项目审核账号及一个只读账号，三者都须有该项目相应授权；不能用同一人自批。
2. 在“标准动作”创建模板，指定节点类型、可选项目类型、动作、材料及核实依据。先保持草稿，创建同类型节点：节点保存成功，配置结果显示模板待批准，不自动关联。
3. 用独立审核账号批准该模板。继续创建一个同范围节点：保存后结果自动出现，显示模板名称、版本及真实动作数量。查看关联动作，核对清单、责任部门、核实要求和自动来源。
4. 保持提醒规则缺失：查看提醒规则显示待配置。由管理员创建公共规则，检查草稿阶段显示待批准；由独立人员批准。回节点抽屉“重新检查配置”，确认自然日天数、提醒日期和接收角色。若角色没有已授权启用账号，仍须显示阻塞原因。
5. 验工作日：使用有明确每日工作/非工作标记的已批准企业日历，核对倒推日期。使用覆盖不足或已停用日历的情况，应显示不可计算原因，不宣称可以成功发送。
6. 创建第二套同范围批准模板，再添加节点：显示两个候选，不自动选择。点击“选择动作模板”，在原抽屉对比名称、版本、范围和明细；使用一套并保存，确认只写入明确选择的动作。重复保存不增加重复关联。
7. 创建没有可用模板的节点：必须保存成功并可稍后返回。有公共配置权限时可进入维护；无权限时只显示联系管理员的说明，不提供绕过审批的操作。
8. 创建勾选“仅进行节点计划及完成情况跟踪”的节点：显示仅时间记录，无需动作/规则，不作为异常。返回列表并刷新，按“仅时间记录”筛选，应仍能找到它。
9. 在保存结果点“继续添加节点”：直接进入同项目、同版本的新节点表单，不重复选择项目和计划。也可随时“返回节点列表”。检查原字段及配置状态列，分别按待关联、待选择、待批准等筛选。
10. 完成整版节点编制后，换独立审核账号打开节点详情，点“前往计划审批”，进入已有整版审批表单并明确填写批准依据。编制账号不能自批；保存节点时不会强迫立即审批。
11. 生效后建立增量草稿，不改动节点：检查原动作引用、任务及提醒没有复制。需要调整时编辑单个节点；旧版本继续只读。可明确切换为仅时间记录并填写原因，检查原动作快照保留且新版本显示暂不执行；整版批准前旧生效版本继续按原规则执行。恢复普通跟踪时只使用仍合法的原关联，不重复创建关联。
12. 在节点页导入 Excel，保留原字段，也可映射选填“仅时间记录”列。准备唯一模板、多候选/待批/无模板及仅时间记录等行。预览核对分类计数，此时台账中没有正式节点。
13. 确认导入，核对后端实际写入数量、自动关联数及每行配置状态。多候选集中留待处理，不逐行弹窗；返回节点列表按配置状态筛选。重复提交同一批次不能重复写入。异常/重复行须修正后重新预览，不做部分导入。
14. 配置检查请求失败后使用重试入口，恢复后应清除错误并显示实际结果；规则或模板改变后主动重新检查。
15. 由原提醒引擎在满足批准状态、触发日和有效接收人的条件下生成站内通知与任务。再按原流程分派、提交反馈、独立核实，必要时明确核实节点实际完成。检查没有把标准动作关联、反馈接受或准备动作完成误当成实际收付款。
