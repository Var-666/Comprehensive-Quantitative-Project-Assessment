## 总览数据与接口边界

仅新增只读接口 `GET /api/v1/metrics/dashboard?as_of=YYYY-MM-DD`。其余业务 API、数据库和数据结构不变；没有新增迁移。

- 趋势为最近六个完整自然月，按计划到期月份分组，使用当前生效计划及当前已核实事实，调用原有 `trial_v1` 分类复算各月末；不冒充历史系统知情快照，也不把之后才完成的节点填回之前月末。
- 待办来自授权项目中尚未 `verified_done` 或 `cancelled` 的真实任务，按截止日排序，列表展示前三项；不是未经确认的“未来七天”业务规则。
- 异常 KPI 明示为延期完成与已核实逾期未完成之和；待核对不推定为延期，无综合评分。
- 节点页复用现有项目指标接口。草稿不作为评价依据，显示“—”及说明；全部计划节点包含已排除记录，其他指标沿用后端分类。
- 项目详情直接读取既有项目指标及待处理任务接口，待办小卡明确只展示 `todo` 状态，其他状态通过执行任务页面查看。已确认完成数量直接使用后端 `verified_completed`，没有新增项目完成率或加权公式。
- 新接口沿用 `visible_projects`，不赋予系统管理员跨项目业务阅读权限。测试验证无权限无泄露、空数据不伪造、只读不写审计、月末日期与批准计划边界。

## 原型冲突及保留的业务差异

1. 原型节点编号写“系统自动生成”，现有 API 要求明确节点编号；保留现有字段和校验，没有新增自动编号规则。
2. 原型将标准动作/提醒直接放在新增节点表单，现有流程在节点保存后关联已批准模板及规则；保留批准与版本机制，表单说明指向实际流程。
3. 原型把项目类型等标为必填，而现有 API 部分字段可选；没有为了视觉新增必填限制或改变字段名称。
4. 独立计划批准、通知发布、执行核实、财务授权、报告快照与审核、安全设置等现有控制比演示稿更多，保留这些操作和状态。节点抽屉的区段导航滚动到原有内容，不隐藏实际记录或变更历史。
5. 总览没有已批准的月度业务快照，只提供明确标注的复算口径；模拟样本某些月份无数据，显示零或空状态，未照抄演示柱高和待办。
6. 原型没有完整的加载、网络错误及全部扩展配置界面稿；沿用已读共享组件、颜色与状态规范实现，未伪称存在这些专用 Frame。
7. 原型节点页整条轨道 SVG 含固定五个位置与演示状态。实际节点数量、排序和状态由 API 决定，不能原样把其颜色当作业务事实；使用动态轨道和从原型下载的独立状态 SVG，保留自然尺寸，不修改矢量路径。

以上差异源于“原型规范视觉、现有系统规范业务”的要求。当前验收不等同于企业正式业务验收或所有动态文本逐像素相同。
