# 第三阶段验收基线（2026-10-20）

用户已明确答复“采用上述验收基线”：按 Excel 试算口径 O/(O+L)，单列待核对、延期完成、已核实逾期未完成与核实覆盖率；不生成未经确认的综合评分。计划和实际资金分开，金额读取、财务录入、独立核实另行授权。编辑生成报告，另一审核人批准。默认明确标记 Mock；真实模型需环境配置和本次显式外送同意。

## 确定性统计

`trial_v1`：D 为所选计划内截至业务日已到期且未取消的节点；O/L 分别为实际日期不晚于截止日的已核实按期/延期完成。O/(O+L) ×100，保留一位小数；分母为零返回 null，不显示0%或100%。完成事实核实覆盖率为 (O+L)/D。汇总先求数量之和，不平均项目百分比。

实际记录未核实、完成情况未知、已核实完成但日期晚于截止日，均不作为本次已完成事实；已明确核实尚未完成的到期节点单列，不冒充延期完成。取消或不纳入所选计划的节点排除。可指定已生效或已取代的计划基准；草稿不能评价。未核实合同性质单列数据质量提示，不把试算当正式合同考核。

业务截止日与系统知情时间分离：按计算时已知的核实事实复算业务截止日，不声称重放“当时系统知道什么”。原 Excel 的夹具没有历史核实时刻，故不伪造历史时间。快照冻结计算时间、公式版本、计划来源、全部节点/实际记录和 SHA256 摘要。后续事实变化另建快照，不修改旧快照；同样事实复用快照。

## 财务边界

财务计划与实际使用不同表、日期及金额字段；实际必须手动给出发生日期、金额及来源。金额为 Numeric(18,2)/Decimal，API使用十进制字符串，不用浮点计算；按币种和收付款方向分别汇总，不作汇率换算。无已核实实际记录返回 null，不能解释成0、未发生或欠款，不声称台账完整。当前是项目事实记录，不是完整会计/对账系统。

项目管理员/系统管理员对已有项目成员明确配置额外读取、写入、核实权；仍需基础项目角色，权限不能替代项目编辑/审核角色。提交人不能核实自己的实际记录。金额报告列表、详情、导出均重新检查财务读取权，撤销后立即拒绝。写入和核实留审计，记录不允许无痕改写；退回或争议后的更正使用新编号和来源说明。

Excel06币种未单独给出，模拟初始化必须调用者显式指定 `--currency CNY`，记录该假设；6条计划只生成1条有实际日期与金额的实际记录。全部为虚构测试事实；不向真实企业项目写样本，不默认授予财务权限。

## 报告与模型边界

报告冻结评价快照和（可选且获授权的）财务事实，支持阶段评价、异常分析、工作安排三个整理标题。引用编号、文字、日期、金额、状态由后端根据事实包渲染。异常正文最多展示80条，并显式提示其余数量，完整证据仍保存在快照。没有自动因果/责任判定、综合评分或资金到账推断。

Mock 是确定性事实整理，页面、正文和导出均标识，无模型请求。真实模式通过现有 httpx（BSD-3-Clause）调用 OpenAI 兼容 Chat Completions JSON Schema 接口，供应商、URL、模型、密钥及超时均来自环境变量。部署开关和本次同意缺一不可；实际外送仅 `{id,section,kind}`，不发送名称、日期、金额、证据正文。模型只排序/分类事实引用及选择建议代码，不能产生自由事实文本。后端检查完整性、重复、越界引用、字段和建议白名单；不完整/非法输出、超时和503由代码返回明确错误，不静默回退Mock，不自动重试，不跟随重定向。没有真实模型凭据时，仅验证 HTTP 合约替身，不冒充真实供应商联调。

报告提交/审核使用 If-Match，幂等生成使用 Idempotency-Key。所有编制与提交人员不能审核该报告；审核事件绑定正文摘要。2026-10-22起，新触发的规则提醒使用确定性模板自动站内投递；升级前历史通知草稿的AI整理仍保留原事实快照及原审核、发布流程。HTML导出保留 Mock/审核状态、快照ID和摘要，转义业务文本并禁用脚本/外部资源；可由浏览器打印PDF，无服务端PDF假实现。
