## 真实业务流程

节点创建后的抽屉配置结果、提醒检查、仅时间记录及导入汇总现已实现，完整规则与手动验收见 [节点配置引导](NODE_CONFIGURATION_GUIDE.md)。仅时间记录节点不作为缺少动作/规则的异常，不生成准备提醒，工作台显示节点进展跟踪。

已批准模板 → 新草稿节点唯一匹配并保存动作快照 → 计划独立审批 → 已批准提醒规则满足触发日/追补窗口 → 自动站内通知与未分派任务 → 人工分派、反馈与独立核实 → 明确确认节点实际完成并核销 → 量化评估和报告。

标准动作和节点计划可以并行准备，参考路径不是强制线性流程，也不代表完成百分比。自动关联不批准计划、不触发正式提醒、不分派人员、不确认任务/节点完成、不确认收付款；原提醒规则与独立核实边界继续生效。外部渠道保持关闭。

## 工作台推荐规则

独立规则服务：`backend/app/workbench.py`。读取当前登录用户的有效项目角色，批量读取所选生效/草稿版本的完整节点视图、模板、关联、提醒规则、日历、有效接收角色、任务、反馈及节点实际记录。推荐接口不调用大模型、不读取财务表、不写业务记录。

排序依次采用：

| 优先级 | 真实事项 |
| --- | --- |
| 10 | 截止日已到、明确分派给当前账号且当前账号仍有项目编辑权限的任务 |
| 20 | 当前账号有权限且满足独立性条件的计划审批、任务反馈核实、节点实际核实 |
| 25 | 标准任务核实完成后，由独立审核人员查看节点实际完成/核销条件 |
| 30 | 标准动作冲突/缺失/来源变化，提醒规则、日历或接收角色等前置配置不足 |
| 40 | 计划编制、待分派任务、尚未到期的本人任务、本人退回资料补充 |
| 70 | 本人已提交但待独立核实、需其他独立人员确认的状态 |
| 80 | 自动提醒就绪，或已核实节点可进入现有量化评估 |

同优先级先展示可操作事项，再按明确日期、项目编号、稳定事项 ID 排序。首页仅显示一个主推荐和最多两个辅助事项。展示项目、具体事项、已提供的截止日期和操作入口；不重复显示阶段、状态及推荐标签，无权限时保留阻塞原因且不给执行按钮。

- 没有可访问项目：系统管理员可进入项目管理页创建项目，首页不放新建入口；其他账号提示联系管理员授权。
- 计划未生效：编辑可完善节点；只有有项目审核权限、未参与编制、有节点且版本确为草稿的账号才获得审批入口。其余账号显示等待状态。
- 缺少动作或存在多候选：编辑进入对应节点检查；配置管理员可维护公共模板。只读用户只看到原因。
- 自动提醒完整且没有本人待办：显示就绪，不伪造任务、异常或重复要求已完成的步骤。
- 任务只按实际分派人与项目权限推荐为“我的任务”；其他人的任务不会归给当前账号。
- 审核入口排除本人提交的反馈与实际记录；编制人不能通过推荐入口自批计划。
- 项目/节点关闭、旧来源、停用模板、无效提醒引用不能推荐为可执行任务。角色撤销在后续请求立即生效。

新增推荐查询使用批量版本解析和目录查询；定向测试比较无节点与100个节点时的 SQL 数量，防止随节点产生 N+1 查询。原有首页统计接口保留，不将新增推荐服务的查询结论扩大为整个统计模块已重构。

## 自动匹配及关联规则

独立匹配服务：`backend/app/action_matching.py`；匹配适用范围复用 `workflow.applicable/scope_applies`，写关联复用 `workflow.link_actions`，节点增量沿用 `plan_item_ids/materialize_plan_item`。

| 实际状态 | 行为与界面 |
| --- | --- |
| 唯一已批准且项目类型/节点类型适用的模板 | 新建或正式导入的本版草稿节点自动关联模板全部动作项，显示“系统已自动匹配”及数量 |
| 多个已批准候选 | 不自动选择、不写关联，展示候选名称、版本、动作、默认责任部门及核实依据，人工勾选确认 |
| 没有适用模板 | 不生成关联或无依据任务，说明缺失原因 |
| 只有适用的草稿/待审核模板 | 显示“模板待业务确认”，不能用于自动关联 |
| 原有有效人工关联 | 原记录、快照、来源保留，不被自动匹配覆盖或追加替换 |
| 原关联已失效或不再适用 | 显示“原动作关联需复核”，历史快照不改写；在草稿版本显式确认新动作 |
| 生效/历史计划或无写权限 | 只检查匹配状态，显示“当前节点不允许修改”，禁止直接修改批准快照 |

自动触发仅覆盖手工新增节点、Excel **正式确认**新增节点，以及新计划中的新增节点。导入预览不会触发。历史节点只读检查，不自动批量补配；已有节点可以在草稿版本中通过现有人工关联入口确认。未提供历史批量补配功能。

继承且未改动的节点继续使用原关联，不因建新版本重复关联。显式修改节点类型时，本版复制出的不适用关联保留记录并标为失效，审计说明来源变更；原版本不受污染。项目类型变化不会自动替换人工配置，读取显示需复核，执行/发送继续校验适用范围。

### 事务、并发与来源

- 所有关联在节点创建或导入的同一业务事务内完成；导入任一行关联失败，整批节点和关联回滚，沿用已有拒绝提交审计。
- 项目/计划锁、节点编号唯一约束及 `(plan_item_id, template_item_id)` 唯一约束防重复。相同节点创建再次提交返回编号冲突；导入幂等键重试返回原结果；相同人工关联重试不重复插入。
- 自动匹配在写入前锁定并刷新唯一批准模板，再复查适用性和候选数量；人工关联也锁定模板并校验批准状态。停用/替换不会让旧快照无声变成新内容。
- 来源保存在现有不可随意改写的动作 JSON 快照：`link_source=automatic_node_create / automatic_excel_import / manual`，同时保存模板名称、编号、版本、动作与核实依据。自动关联写 `auto_link_action` 审计；旧记录无来源字段时按历史人工配置展示，不补写数据库。
- 历史开发样本加载没有登录用户，不自动补配动作或伪造模板批准。
- 复用现有表与 JSON 快照，无新增依赖，无数据库迁移。

## API 与操作入口

| API | 内容 |
| --- | --- |
| `GET /api/v1/workbench/next-actions` | 只读、经过项目权限过滤的 `primary`、最多两项 `secondary`、项目阶段及业务日期；事项含原因、状态、业务类型、目标路径和阻塞说明 |
| `GET /api/v1/milestones/{id}/action-matching?plan_version_id=...` | 只读匹配状态、可修改资格、候选差异、已有快照及自动/人工来源；校验节点与计划属于同一项目 |
| 现有节点新增、编辑、列表、详情 API | 增加 `action_matching`；列表只返回摘要，详情及新增结果含完整候选和关联 |
| 现有 `GET .../suggested-actions` | 保持原候选接口可用 |
| 现有 `POST .../action-links` | 沿用人工确认入口；明确选择草稿计划及节点，可传 `plan_version_id` 处理继承节点；批准/历史版本拒绝写入 |

推荐链接可直接打开指定节点或任务详情；提醒配置链接进入“标准动作”的提醒规则页签。新建节点成功后直接打开同一个节点抽屉的配置结果，可查看动作、展开提醒规则、返回节点列表或继续添加；多候选在抽屉内选择，不叠加业务弹窗，不强制逐节点审批。

## 如何在现有系统验证

1. 使用既有启动方式启动当前前后端和扫描进程；无需额外初始化业务数据或迁移。系统管理员编制模板，由独立审核人批准，配置适用项目/节点类型及动作。
2. 项目编辑在本项目草稿中新增适用节点，保存后查看自动匹配结果及数量；进入详情“标准动作”查看版本、责任部门、核实依据和来源。
3. 再批准另一个适用模板后新增同类型节点，应显示多候选且没有自动关联；显式勾选确认后显示人工来源。只有待审核模板时不能自动关联。
4. 使用现有节点 Excel 导入入口：预览时不应出现业务节点或关联；正式确认后在节点台账查看自动匹配。历史/批准节点不会因查看而被补写。
5. 返回首页，查看推荐事项及原因。编辑、独立审核人、只读账号分别登录，对比可操作入口；点击应进入所指节点/任务详情。
6. 独立批准计划和提醒规则，按真实规则等待触发日（隔离测试可模拟业务日期），确认站内消息及未分派任务，重复扫描不重复生成。再人工分派、反馈、独立核实，检查节点核销及量化入口。
7. 在1440、1280、1024px检查推荐文字、按钮、参考路径及原统计模块；截图和实际定向测试结果记录在下节。
